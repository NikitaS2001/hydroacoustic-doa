# Repository Guidelines

## Project Overview

Исследование направления прихода (DOA) одного подводного источника на измеренной линейной решётке.
Код содержит цифровые пилоты, не полный метод JEPA/Fusion. Статусы и блокеры — в [README](README.md).
Срок текста — **2027-03-31**; размеченная подлёдная натура зимы 2026–2027 обязательна.
Минимум JEPA/ресурсы/публикационные требования ещё согласуются с руководителем.

## Architecture & Data Flow

`src/` отсутствует: код — самостоятельные синхронные Python-скрипты, не приложение или устанавливаемый пакет.
NumPy-пилоты: синтетика → задержки/шум → оконное преобразование Фурье (STFT) → парные признаки → диагностический считыватель → JSON.
PyTorch-пилот: синтетика → STFT → энкодер/декодер реконструкции → отдельный считыватель → метрики/веса.
`mono_phase_crosscheck.py` зависит от результата `mono_phase_feasibility.py`.

Проектируемый метод использует Re/Im STFT → поканальный энкодер E → допуск задержки/фазы → межсенсорный Fusion.
Re/Im — действительные и мнимые части. Допуск проверяет замороженные параметры **и состояние** E.
Точные маски, цели до агрегации и параллельные ветви с новыми головами задаёт [метод](docs/method.md).

## Key Directories

- `experiments/`: код и первичные результаты, включая неудачи; это не кэш. `encoder_phase_pilot/` содержит малые сети, `ula_evidence/` — внешние сводки.
- `tools/`: автономный stdlib-валидатор; `docs/`: действующие спецификации; `outputs/`: тематические обзоры доказательств.
- `notes/`: решения, задачи, происхождение редакций и проверки; `papers/` предназначен для будущих статей.

## Development Commands

Из корня репозитория:

```bash
python3 -B tools/validate_repository.py --self-test
python3 -B tools/validate_repository.py
git diff --check
uv run --locked --offline python experiments/signal_geometry_check.py
```

Последняя команда только печатает арифметику при допущениях, не измеряет аппаратуру.
Сборка, линтер, форматтер и общий тестовый runner не настроены; не придумывайте команды pytest или сборки пакета.

## Code Conventions & Common Patterns

- Следуйте локальному стилю: функции `snake_case`, классы `PascalCase`, конфигурации через константы/словари, результаты в JSON.
- Задавайте seeds явно: `np.random.default_rng(seed)`, генераторы PyTorch и CUDA seeds. Сохраняйте парность условий и родительские группы.
- Используйте существующие `assert` для инвариантов. Не скрывайте неизвестные режимы и превышение бюджета запасными результатами.
- Серверных async/DI-слоёв нет. Модели сохраняются через `state_dict`; общего механизма продолжения обучения нет.
- Сохраняйте задержки/фазу, порядок каналов и общий масштаб. Не выравнивайте пики и не нормируйте каналы независимо.
- MSE сырых компонент — обучение; круговая ошибка — оценка. Не обрезайте углы и не назначайте угол нулевому вектору.
- Перед правками смотрите `git status`; сохраняйте чужую работу, не выполняйте reset/clean. Структурное удаление требует снимка и карты миграции.
- Коммит/push требуют разрешения; не выдумывайте автора и не задавайте его глобально.

- [Оценка](docs/evaluation.md): S/R/E1/final и независимые единицы; [зимний протокол](docs/experiments/winter_field_protocol.md): безопасность, истина, калибровка.
- [Осенняя инструкция](docs/experiments/bench_signal_trial.md): защищённая автономная проба одной геометрии, не зимний угловой тест.
- [Глоссарий](GLOSSARY.md): термины; `notes/refactor_manifest.json`: хеши, подписи, допустимые файлы/адреса и Markdown-бюджет.

Не возвращайте VAE/HuBERT-матрицу. Не заявляйте однозначные 360°, произвольные физические массивы, проверенную физику льда или новизну без доказательств.

## Runtime/Tooling Preferences

Python **3.12.14**, менеджер **uv**, `package = false`; системный Python не изменяйте.
`pyproject.toml` задаёт зависимости, `uv.lock` фиксирует версии/хеши, `.python-version` выбирает Python.
NumPy — 2.4.2; PyTorch из explicit-индекса `pytorch-cu128`, lock фиксирует `2.11.0+cu128`.
Среда ориентирована на Linux/CUDA; другие платформы не проверены. GPU-пилот и smoke требуют CUDA, без молчаливой замены на CPU.

Установка при необходимости: `uv sync --locked`; подготовленная среда: `uv run --locked --offline`.
Не устанавливайте зависимости ради документационных правок.
Внешний код требует согласованного места, закреплённого источника и проверки лицензии/зависимостей/безопасности/соответствия; не вкладывайте чужие репозитории по умолчанию.

## Testing & QA

Встроенные фикстуры — в `tools/validate_repository.py`; общего pytest-набора и порога покрытия нет.
Валидатор проверяет регистрацию, ссылки, таблицы, хеши и сводки, не научный смысл или аппаратуру.
`--snapshot` требует внешних архивов и имеет известное ограничение после содержательных редакций; это не переносимая проверка.
До кода/расчётов запишите проверки; выполните их и сохраните результаты.

Не запускайте исследования ради проверки документации:
- `synthetic_stft_tdoa.py`, `mono_phase_feasibility.py` и `uv_environment_smoke.py` перезаписывают соседние JSON.
- `mono_phase_crosscheck.py` исполняет расчёт и пишет JSON даже при импорте.
- `encoder_phase_pilot/autoresearch.sh` обучает модели; `verify.py` загружает внешние веса, повторяет обучение и перезаписывает отчёт.
- `encoder_phase_pilot/summarize.py` перезаписывает раздел обзора.

Разрешённые повторы выполняйте на изолированных копиях; исходные результаты и raw не перезаписывайте.
Большие данные/веса/секреты/кэши — вне Git; архивы — с хешами/калибровкой/реестрами и двумя проверенными копиями.
Делите группы до окон/каналов. Закрытые данные/фон/производные не используются для подгонки модели/учителя/нормировки/симулятора/выбора.
Реальному A/R нужен проверенный `D_hat`, не команда/преамбула.

Решения/неудачи/проверки фиксируйте в датированном журнале; обновляйте задачи и регистрируйте редакции/новые файлы.
Не подменяйте архивные хеши/исходные подписи; при смене заголовков обновляйте ссылки/карту адресов. HTML-id запрещены.
Проверяйте изменения чтением/diff; числа/URL/изменчивые утверждения сверяйте с первоисточником.

Один русский канон; код/пути/формулы/первичные логи/библиографические названия сохраняйте.
Термины поясняйте по-русски с английским эквивалентом при первом употреблении; язык статьи задаёт издание.
Различайте наблюдение, условный расчёт, предложение, непроверенное, непройденное и невыполненное.
Завершайте работу артефактом, проверками и блокерами; безопасность/истина/зимние доказательства важнее дополнительных экспериментов.
Неудачный допуск E блокирует основной Fusion, не классику/обучение с нуля. Цифровой успех, литература и Git не доказывают научный результат.
