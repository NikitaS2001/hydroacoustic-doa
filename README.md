# Hydroacoustic DOA — кандидатское исследование

Исследуем, может ли обучение представлений улучшить оценку азимута одного подводного источника на измеренной линейной решётке.
DOA (direction of arrival) — направление прихода сигнала.
Обязательны контролируемая симуляция и независимые размеченные подлёдные измерения **зимой 2026–2027**.
Полный текст диссертации нужен к **31.03.2027**.

**Научный статус на 20.10.2026:** есть ограниченные цифровые результаты, но полный метод и полевая часть не подтверждены.
Нет принятого полевого набора, проверенного водного тракта, полного E-M/обученного Fusion, допуска замороженного E или измеренного выигрыша полного метода.
Формальный минимум M3/всех стадий JEPA, бюджет и публикационные требования ещё согласуются с руководителем.
JEPA предсказывает представления, а не исходные отсчёты.

STFT — оконное преобразование Фурье; TDOA — разность времени прихода.

## Задача и гипотеза

Задача ограничена одним азимутом в обследованном идентифицируемом секторе при известном/ограниченном угле места.
Линейная решётка сама не разрешает неоднозначность «перед/зад» или азимут на 360°.
Координатный вход и симуляция геометрий не доказывают перенос на произвольные физические массивы.

Основной вход — действительная и мнимая части оконного преобразования Фурье (Re/Im STFT).
Один общий поканальный энкодер E кодирует датчики независимо; Fusion объединяет их признаки.
Проектируемая последовательность:

```mermaid
flowchart LR
    X[Re/Im STFT] --> E[Этап 1: четыре рецепта E]
    E --> G{Заморозить E и состояние; проверить TDOA и фазу}
    G -->|допуск пройден| F[SSL Fusion]
    G -->|не пройден или отсутствует| B[Блокировать основной Fusion]
    F --> C[Один checkpoint E+Fusion]
    C --> H[3a: замороженные E+Fusion; новая голова]
    C --> J[3b: совместное дообучение; другая новая голова]
```

При допуске проверяются знак TDOA и относительная фаза.
Сравнения выполняются с исходным входом и необученным E.

SSL (self-supervised learning) — самообучение; checkpoint — сохранённое состояние модели.
Fusion обучается только по скрытым доступным позициям, с целями EMA до агрегации.
EMA (exponential moving average) — экспоненциальное скользящее среднее параметров учителя.

Следующий **инженерный пилот**, не утверждённый минимум M3, сравнивает четыре рецепта только по наблюдениям (observed-only):
- reconstruction Re/Im;
- TS2Vec-like timestamp agreement;
- observed-JEPA;
- hybrid.

Все используют **одну существующую гибридную основу и единый интерфейс E**, без перебора архитектур.
Прямой компонент D не входит в их SSL-цели.
A/S с D — отдельный привилегированный вариант сравнения; B — отдельная будущая задача.
Точные интерфейсы, маски и открытые настройки задаёт [метод](docs/method.md#этап-1-поканальные-варианты), не эта схема.

Обязательные сравнения: обучение с учителем с нуля, вариант без координат, **MVDR/Capon и MUSIC**.
Bartlett служит диагностике. Голова обучается по MSE сырых `(a,b)` к `(cosθ,sinθ)`; круговая ошибка и отказы оцениваются отдельно.
Это гипотеза, не результат. Прежняя матрица VAE/HuBERT/пяти энкодеров отменена.

## Что делать дальше

**Модельный приоритет — четыре рецепта E, не Fusion.** Аппаратный/полевой допуск идёт независимо; синтетика его не заменяет.

1. **Подготовьте тракт и банк:** подтвердите такт/каналы/полосу/уровни, точные команды и критерии приёмки.
   Банк **не создан**; цифровая source() — не пакет воспроизведения.
2. **Проведите разрешённую водную пробу:** одна геометрия проверяет тракт и сигналы, не зимнюю угловую точность.
   Запись, калибровка, истина, фон/хвост, отказы и копии — по [автономной инструкции](docs/experiments/bench_signal_trial.md).
3. **Выполните модельный пилот:** проверьте аналитический генератор/ReIm STFT/парный baseline; зафиксируйте настройки и бюджет.
   Затем сравните четыре рецепта и проверьте допуск E. Численные настройки и формальный M3 ещё не утверждены.

Восемь гидрофонов, ≈27 мм и 96 ksample/s/«32 bit» — номиналы, не подтверждение геометрии/такта/полосы.
LFM 4–20 кГц/50 мс и STFT256/64 — кандидаты. Уточнения и анализ hop64/128 — в [акустическом обзоре](outputs/acoustic_frontend.md).
Обучение с нуля/классика, зимняя подготовка и письмо не ждут успеха SSL.

Отдельный [пилот зонда и обнаружения](outputs/acoustic_frontend.md#кандидатный-пилот-зонда-и-обнаружения) предложен, **не выполнен**.
Он сравнивает ЛЧМ с одной PN/QPSK-кандидатурой, опорное/многоканальное обнаружение и общее окно.
Он не заменяет E или полевые допуски.

## Правила доступа и короткий словарь

- **S:** подгонка/выбор только на разрешённой симуляции; закрытая натура оценивается без подгонки по целевым сценам (zero-shot).
- **R:** отдельно разрешённые неразмеченные реальные группы/операции, без угловых меток и подгонки симулятора.
- **E1:** отдельная адаптация с реальными метками. Ни один режим не открывает итоговые данные для подгонки.
- Отдельная фиксированная приборная калибровка общая для методов; она не разрешает подгонку по итоговым сценам.
- Группы разделяются **до окон/каналов**. Окна, повторы и начальные состояния генераторов (seeds) не создают независимых сеансов.
- Исходные записи (raw) неизменяемы, с хешами и проверенными копиями.

Реальному `D_hat` нужна отдельная проверка качества/покрытия; A/R сейчас заблокирован.
Определения — в [глоссарии](GLOSSARY.md), полный режим доступа — в [протоколе оценки](docs/evaluation.md#1-доступ-к-данным-и-независимые-единицы).

Один русский канон; код/пути/формулы/первичные логи/библиографические названия сохраняются.
Правила языка и адресов заголовков — в [руководстве](AGENTS.md); старые внешние адреса не гарантируются.

## Быстрый старт

Для чтения и переносимой проверки документации достаточно Python 3; устанавливать PyTorch не нужно.

Для **запуска экспериментов** нужна среда Python 3.12.14 через uv.
Конфигурация находится в `pyproject.toml`/`uv.lock`/`.python-version`; проект не собирается в пакет.
Среда ориентирована на Linux/CUDA 12.8, другие платформы не проверены.

```bash
# Установка зависимостей; может загрузить крупные CUDA-пакеты.
uv sync --locked
# После установки: только арифметика, без обучения и перезаписи результатов.
uv run --locked --offline --no-sync python experiments/signal_geometry_check.py
```

Это расчёт при допущениях, не проверка аппаратуры или точности DOA.
Не запускайте обучающие пилоты как общий тест: некоторые скрипты перезаписывают JSON, веса и разделы обзоров.
Безопасное повторение требует изолированных копий; подробности — в [AGENTS.md](AGENTS.md#testing--qa).


Это **не** научная валидация текста, оборудования или модели.
Новый клон проверяет текущий состав; без локальных снимков он не подтверждает восстановимость старой незакоммиченной истории.
