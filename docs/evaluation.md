**Канонический план оценки · 2026-09-27.** Документ не утверждает наличия набора данных, обученной модели, пройденной полевой проверки или результата DOA. [План проекта](project.md) определяет объём/календарь; [метод](method.md) — точные интерфейсы предобработки/модели/обучения; [зимний протокол](experiments/winter_field_protocol.md) — метрологию, безопасность, съёмку и приёмку архива. <a id="1-data-access-and-independent-units"></a>

## 1. Доступ к данным и независимые единицы

Обязательны два вида доказательств: физически проверенная симуляция измеренной линейной конфигурации и **размеченные натурные подлёдные данные зимы 2026–2027**. Наложение реального шума и осенняя проба при фиксированной геометрии не заменяют зимние доказательства DOA. Ни один полевой набор проекта пока не принят.

| Режим/материал | Разрешённые подгонка и выбор | Запреты / интерпретация |
|---|---|---|
| **S: неизменный режим только симуляции** | Разрешённая симуляционная разработка для E/Fusion/EMA, предикторов/проб, нормировки, симулятора, выбора архитектуры/checkpoint и обучения с метками | Без подгонки по реальным сценам, включая безметочные/шумовые фрагменты. Последующая оценка на закрытой натуре — zero-shot |
| **R: отдельно разрешённые безметочные реальные данные разработки** | Только перечисленные правомерно доступные группы и операции, разрешённые **до** доступа, включая использование учителем, нормировку и выбор | Без подгонки по азимутным меткам или настройки симулятора; без закрытых групп; это не S zero-shot. По умолчанию сохраняется масштаб S, если переоценка не разрешена |
| **E1: адаптация с реальными метками** | Отдельно согласованные группы разработки, малый бюджет меток, названные обучаемые параметры/исключения для нормировки, вычисления/seeds | Не R и не zero-shot; неизменные результаты S и, при наличии, R показываются отдельно |
| **Закрытые итоговые симуляционные/реальные данные** | Только применение зафиксированного метода, расчёт метрик и заранее заданный QA; реестр доступа только дополняется | Нельзя подгонять энкодер/учителя, нормировку, симулятор, аугментации, маски, пороги, раннюю остановку или выбор; нельзя переводить в разработку |
| Отдельная приборная калибровка / физический замер | Заранее заявленные фиксированные поправки/физические входы при применении, одинаковые для методов, кроме объявленной координатной абляции | Не подгонка по целевой сцене или меткам; без привилегий из записей итоговых сцен |

Разделять по **независимой родительской группе до извлечения каналов/окон**. Окна, каналы, шумовые наложения, цели, признаки и все производные наследуют доступ. Для каждой подгонки записывать ID файлов/групп, доступные метки, назначение и версии. Нет R → **не выполнено**, а не переименованный эксперимент S. Для A/R дополнительно нужен независимо проверенный оценённый `D_hat`; известная команда/преамбула не является прямой компонентой. B/R предсказывает будущие наблюдаемые окна с непересекающейся полной поддержкой. Варианты и допуски определены в [методе, §5](method.md#5-three-stage-jepa-and-gates).

**Единицы статистического вывода:** независимые симулированные среды; независимо полученные полевые группы «установка/сеанс/день» с обоснованными границами зависимости. Окна/перекрытия, направления, посылки, seeds источника/шума, программные подмножества датчиков и seeds обучения — вложенные наблюдения. Несколько независимых полевых групп, желательно не менее трёх сеансов/дней с повторной установкой, — цель безопасной и выполнимой съёмки, не утверждение мощности. Первая пригодная группа может быть DEV_QA; независимые итоговые группы резервируются до выбора модели. Для заявления о реальном тесте нужны группа, допустимая для разработки, и отдельно зарезервированные итоговые группы. Один пригодный сеанс позволяет описательные выводы внутри него, не перенос между сеансами или уверенность из бутстрэпа окон.

<a id="field-eligibility-and-custody"></a>

### Пригодность полевых данных и хранение

Каждый принимаемый размеченный блок требует raw с общим тактом или эквивалентно доказанной синхронностью; фактических подводных положений/глубин источника и датчиков, системы координат/ориентации и неопределённости; идентичности/времени источника из независимого журнала; известного идентифицируемого сектора при фиксированном/известном угле места либо измеренных ограничениях, показывающих пренебрежимость его влияния; обоснованного дальнеполевого или учитывающего дальность анализа; калибровки порядка/полярности/усиления/фазы/времени каналов; соответствующего фона до/после; неизменяемых raw/хешей/повторно открытых копий и статуса группы/доступа. Плановые лунки или направления не являются истиной. Документировать движение кабелей, направленность/ориентацию источника, дрейф такта и отклонения среды/режима работ.

Raw неизменяемы и хранятся вне обычного Git. Сохранять две проверенные копии в независимых местах по правилам учреждения. Повторно открывать намеченным считывателем и проверять частоту/формат/каналы/длительность/читаемость отсчётов. Несоответствия хешей, читаемости, метаданных, такта или истины отправлять в карантин, а не молча переводить в обучение. Сохранять отказы/остановки, плохие каналы с масками качества и попытки съёмки; решения по качеству фиксируются до итоговой оценки и не зависят от сравнительной ошибки. См. полевые [допуски](experiments/winter_field_protocol.md#2-decision-register-and-evidence-gates) и [архивирование](experiments/winter_field_protocol.md#5-archive-quality-assurance-and-access-controls).

QA-доступ к закрытым группам не должен влиять на выбор метода. Отдельно зафиксированная приборная калибровка может быть общим входом; метки/поправки, полученные из целевой сцены, — нет. Для каждого доступа к итоговым данным записывать время, цель, версии кода/протокола/модели, хеши конфигурации и реестра, выходы и последующие решения.

<a id="2-simulation-qualification"></a>

## 2. Проверка симуляции

Создавать независимые среды для **измеренной линейной решётки** с обоснованной неопределённостью тракта/калибровки/геометрии. Записывать для каждого приёмника `X_m=D_m+R_m+N_m`, прямую компоненту D **с физической задержкой и фазой**, конфигурацию/хеши. Одна форма источника — не D. Слабое/отсутствующее прямое прибытие и неразрешённая ранняя многолучёвость обязательны как диагностика до выводов о реальном прямом эталоне. Исключённые из обучения геометрии — дополнительные исследования, не минимальные конечные результаты.

<a id="physics-and-numerical-checks"></a>

### Физические и численные проверки

1. **Каждый приёмник:** рассчитывать многолучёвость в собственной позиции каждого датчика. Не строить набор распространения сдвигом/поворотом/интерполяцией канала другого датчика. Аналитически сдвинутые копии прямой волны допустимы как **диагностика**, не как полные многолучевые сцены.
2. **Задержка/фаза:** сохранять непрерывные задержки при сериализации и синтезе дробной задержки; без округления до ближайшего отсчёта. Задать допуски из полосы/бюджета ошибки; проверить полный отклик и сходимость по частотной сетке, не только первое прибытие. Установить, включает ли амплитуда решателя фазу распространения, и применять её ровно один раз. Широкополосный синтез должен реализовать линейную свёртку/общее время со всеми участвующими путями; исключить циклический перенос и независимое выравнивание приходов.
3. **Пакетный расчёт:** многоприёмные вызовы заменяют отдельные решения только после проверки эквивалентности всей многолучёвости в заявленных допусках; восстанавливать ID датчиков при перестановке выходов. Учитывать стоимость всех расчётов по приёмникам/частотам/сходимости.
4. **Физический охват:** обосновать размерность, граничные условия, зависимость по дальности/поперечному направлению и опущенные эффекты. Двумерная модель «дальность–глубина» не представляет неучтённую горизонтальную рефракцию/поперечную неоднородность. BELLHOP — кандидат, не проверенная физика льда. Свободная поверхность с нулевым давлением — **не лёд**. Описать представление шероховатости/структуры/шума льда и доказательства; без проверки выводы относятся к общей симуляции/сдвигу домена.
5. **Проверка решателя:** аналитические/эталонные случаи и численная сходимость; ускоренную реализацию сверять с эталоном, не считать независимой физической проверкой. Сравнения независимых решателей требуют совместимых физики/границ. Закрепить репозиторий/ревизию или хеш исполняемого файла, интерфейс, сборку/компилятор/опции/точность и хеши входов; сохранять неудачи проверок и неразрешённые расхождения.

Правила наличия источника и QA генерации задаются заранее. Сохранять отклонённые попытки/причины, ограниченное правило замены и изменения распределения условий из-за исключений. Не выбирать лёгкие примеры по предсказаниям/ошибкам модели. Все методы используют **один зафиксированный реестр пригодных примеров**; отказы методов на нём остаются в оценке.

<a id="noise-and-snr"></a>

### Шум и SNR

Различать собственный шум датчиков, пространственно когерентные акустические помехи и записанные многоканальные фоны. Когерентной помехе требуется собственное распространение либо подходящая многоканальная запись; независимый шум датчиков не является заменой. Сохранять пространственную ковариацию/отношения фоновых каналов и ограничения доступа. Полевые записи контакта со льдом, бурения/установки/подъёма, фона/ветра, судов/работ/оборудования описывают сдвиг условий, но не проверяют модель льда.

Зафиксировать полосу/фильтр измерения отношения, активные датчики, временное окно и агрегацию мощности. Для положительных конечных среднеквадратичных мощностей чистой цели и немасштабированного шума `P_s,P_n` на одной и той же поддержке:

\[
a=\sqrt{\frac{P_s}{P_n10^{\mathrm{SNR}_{dB}/10}}}.
\]

Применять **один скаляр ко всей многоканальной реализации шума**, не отдельные скаляры датчиков/бинов. SIR использует отдельно распространённую помеху и записывается отдельно. Показывать заданное отношение, применённый скаляр и достигнутое отношение в полосе как для массива, так и для каждого датчика. Разные полосы измерения/модели называются явно, не подменяются молча. Нулевая мощность цели → относительное SNR не определено; применять заранее заданное правило пригодности источника и абсолютную мощность шума, не исправление через epsilon. Ненулевая цель без шума явно считается чистой; шум нулевой мощности не позволяет реализовать конечное заданное SNR. Полевое SNR — **оценка** с методом/допущениями, не известная истина компонент.

<a id="3-required-comparisons"></a>

## 3. Обязательные сравнения

| Метод/сравнение | Информация и условия сопоставимости | Интерпретация |
|---|---|---|
| **MVDR/Capon, MUSIC** | Одинаковые разрешённые полоса/длительность, сектор/координатная система, измеренные координаты/калибровка, группы и допущения о числе источников/дальности | Обязательные практические классические сравнения, показываемые отдельно |
| Bartlett / суммирование с задержками | Та же физика; контролируемые проверки знака/направляющих векторов | Диагностика, не достаточный конкурентный метод сравнения |
| Координатная модель с нуля и вариант без координат | Одинаковые выбранные гибридные E/Fusion/голова, метки/вход/ёмкость/оптимизатор/бюджет выбора, парные seeds; убрана только информация из геометрии | Обязательный нейросетевой контроль и вторичная информационная абляция |
| JEPA 3a | Тот же SSL checkpoint, что у 3b, замороженные E+Fusion, обучение только новой головы | Читаемость заданной головой; не оптимальная эффективность |
| JEPA 3b против полного обучения с нуля | Одинаковые разрешённые метки и бюджет/конфигурация последующего обучения; новая голова и совместное дообучение | Практическая польза инициализации; стоимость SSL/проб дополнительная |
| Только этап 1 против этапов 1+2 | Замороженные и/или совместные сравнения, где выполнимо; раскрыть обращение с новым/случайным Fusion и дополнительные данные/вычисления | Выделение эффекта SSL Fusion, не автоматическая дополнительная обязательная матрица |
| B/S против разрешённого B/R | Одна задача с наблюдаемой целью и заявленный бюджет инициализации/обновлений/контроля | Сравнение источников данных, не доказательство превосходства целевой задачи |

Пара с нуля/без координат и обе головы этапа 3 используют одинаковые суммарную MSE сырых компонент, декодирование и обработку отказов из [метода, §4](method.md#4-one-azimuth-head-and-supervised-loss). Координаты входят только в Fusion. Плановая цель: **три парных нейросетевых seed** с согласованным назначением; фактическое число зависит от измеренного бюджета. Если невыполнимо, получить согласованное с руководителем сокращение/изменение вывода до теста, не молча удалить seeds. E-M сначала, E-S при нехватке ресурсов, E-L в резерве — это **выбор одного размера**, не три обязательных обучения.

**Фиксация классики:** снимки/оцениватель ковариации, диагональная регуляризация (diagonal loading), допущение о числе источников, знак/координатная система направляющего вектора, скорость звука/дальнеполевое или учитывающее дальность соглашение, угловая сетка, бины, побиновая нормировка, агрегация частот и выбор пика. Разработать/проверить на контролируемых случаях до закрытых данных. У методов могут быть документированные разные входные представления при одном физическом наблюдении. Истинная дальность из меток — не бесплатный вход наведения: условия известной дальности объявляются и доступны всем одинаково; методы с истинной дальностью или эталонными откликами среды (environmental replicas) — диагностические либо отдельно привилегированные.

**Сопоставимость:** одни пригодные строки, калибровка/версия, время, сектор/угол места/правило наличия источника, родительские группы, исключения/отказы и доступные метки; равные возможности настройки/правила остановки. A/S получает привилегированную симулированную D, в отличие от задач с наблюдаемой целью. Одинаковые шаги последующего обучения не означают равенства всей информации/вычислений. Дополнительные задачи, большие модели или перенастройка классики после проигрыша не являются способом спасти результат. Дополнительные Root-MUSIC/ESPRIT/SRP-PHAT/разреженные методы/согласование поля требуют согласования допущений, доступа и объёма, не автоматического включения.

**Наблюдаемость без координат:** неупорядоченные наблюдения симметричной линейной решётки могут не определять целевое направление со знаком даже после ограничения физической полуплоскостью. На контролируемой разработке диагностировать неразличимые случаи/предел ошибки до итогового сравнения. Восстановление намеренно скрытой информации не является самостоятельной архитектурной новизной или превосходством над сильными нейросетями для фиксированной решётки; такое утверждение потребует дополнительного обоснованного метода сравнения и решения об объёме.

**Проверки достоверности:** [TDOA со знаком/относительная фаза замороженного E](method.md#frozen-e-gate-before-fusion) до Fusion; проверки фазы/когерентности/времени всего тракта; совместной перестановки, соответствия координат, изоляции безкоординатной ветви, подмены скрытого входа, дополнения/полностью закрытого входа, коллапса и поддержки/кэша B. Задать цель пробы как D или X, ёмкость считывателя, группы подгонки/отчётности и пороги. Угол обученного признака не является физической фазой; неудача малой пробы ограничивает проверенную доступность, но всё равно блокирует предписанный следующий этап. Итоговая группа не задаёт пороги. Малый SSL loss, комплексный входной блок и неколлапсировавшие признаки не заменяют допуск.

<a id="4-scoring-and-independent-unit-inference"></a>

## 4. Метрики и вывод по независимым единицам

Для азимута нужны измеренный идентифицируемый сектор/полуплоскость и известный/ограниченный угол места; всем методам даётся одно априорное ограничение. Если его нет, изменить наблюдаемую цель до фиксации. Двухкомпонентная голова или координаты не дают основания заявлять однозначный полный круг.

Для конечного допустимого предсказания:

\[
e_i=\left|\operatorname{atan2}(\sin(\hat\theta_i-\theta_i),\cos(\hat\theta_i-\theta_i))\right|\frac{180}{\pi}.
\]

Аргументы тригонометрических функций — в радианах. Конечные предсказания вне сектора оценивать **как есть**, отдельно отмечая нарушения; без обрезки, отражения или переметки. Отсутствующие/неконечные оценки, вырожденные нейросетевые векторы по общему фиксированному tau и пустые пригодные выходы Fusion — отказы. В основных парных статистиках по всем общим пригодным строкам каждый отказ получает **180 градусов**, максимальную круговую ошибку. Также показывать медиану/p95 только допустимых оценок, покрытие/причины отказов, чтобы пропуски не улучшали ранжирование. Исключения из-за записи/истины следуют заранее заданному QA, не выходам модели.

Для каждой единицы u и метода m:

\[
E_u(m)=\operatorname{mean}_{s\in\text{declared seeds}}\{\operatorname{median}_{i\in u}\,e^{failure-aware}_{i,m,s}\},
\qquad d_u(m,b)=E_u(b)-E_u(m).
\]

Положительное `d_u` — в пользу m. Детерминированная классика даёт один результат, не выдуманные seeds. Сравнения с MVDR и MUSIC остаются раздельными; вариант без координат — вторичное сравнение компонента. Симуляционные агрегаты используют **равные веса независимых единиц**, не число окон. Полевой отчёт сохраняет разность для каждой группы; любое среднее с равными весами групп явно описательное. Seeds — повторные обучения, не дополнительные единицы; не усреднять предсказанные углы, если отдельно зафиксированный ансамбль сам не является методом. Для совместного заявления превосходства заранее задать семейство сравнений/учёт множественности.

Показывать по единице и существенному условию: медиану/p95 с учётом отказов **и** только по допустимым, отказы/покрытие, число отклонений по источнику/QA, нарушения сектора, неопределённость истины/калибровки, интерпретацию скорости звука/дальности/сектора и ресурсы. Средняя абсолютная ошибка/RMSE — вторичные описательные меры. Разбивать симуляцию по исключённой из обучения среде, углу/источнику/шуму/помехе и обоснованным ошибкам калибровки/измерения; натуру — по независимой группе, сектору/источнику/дальности/QA. Дополнительные результаты геометрии оставлять симуляционными и различать S zero-shot, R и E1.

Интервалы и парные анализы должны указывать фактическое число/построение независимых единиц и допущения. Малое число групп требует ограниченного описательного отчёта; ресэмплинг окон не создаёт уверенности в переносе между сеансами. Любой порог практически значимого эффекта, утверждение мощности или размера выборки требуют пилотного/прикладного обоснования **до** итогового доступа; сейчас они не установлены. Граница Крамера–Рао (CRLB) — необязательная диагностика лишь при совпадении правдоподобия, направляющей модели, ковариации, независимых снимков и мешающих параметров; не сравнивать её с медианой/p95 и не подтверждать границей свободного поля точность во льду/многолучёвости.

<a id="5-reserve-comparisons"></a>

## 5. Резервные сравнения

Действуют [ограничения дополнительных работ](project.md#optional-work-and-stop-budget): не более одного согласованного расширения, без новых дополнительных работ после 2027-02-01, целевая фиксация дополнительных результатов 2027-02-15. E1 с реальными метками, E2 чувствительность внутри линейного массива, E3 чувствительность к калибровке/границам, резервный вход или нелинейная топология только в симуляции не заменяют зимний минимум/контроли или отчёт по основным проверкам JEPA.

**Одна альтернатива представления** основной STFT в одном фиксированном опорном режиме обучения:
- те же разрешённые родительские наблюдения/реализации/группы и информация цели, калибровка и сектор, физическая полоса и длительность наблюдения — не длина тензора/число кадров/частота дискретизации;
- точное происхождение преобразования/нормировки/генератора/поддержки; без незаявленного временного контекста;
- одинаковые заявленные правила настройки, seeds, остановки/отказов; раскрыть различия адаптера/архитектуры, ёмкость, эффективную длительность рецептивного поля, параметры и оптимизатор;
- контролируемые проверки фазы/задержки входа/всего E и сопоставимые пробы; потери восстановления/предварительных задач не являются общей шкалой ранжирования;
- измерение всей предобработки/преобразования/обучения/применения/хранения/пиковой памяти, не только пропускной способности по кэшированным признакам.

Больше альтернатив или произведение «вход×SSL» требуют нового решения об объёме до теста. Перенос геометрии также требует исключить целевые раскладки/шаги/топологии из обучения, нормировки, настройки симулятора и выбора, а также задать идентифицируемую область. Успех в поле на фиксированной решётке плюс симуляция геометрий — не физический перенос на произвольную топологию. Физические подмножества датчиков одной установки — наблюдения чувствительности, не новые независимые решётки.

**Фиксация E1:** группы и предел меток; разрешённые обучаемые параметры, например объявленная голова/адаптационный слой; по умолчанию без переоценки нормировки, если отдельно не разрешена; seeds/вычисления; нетронутые итоговые группы и неизменное сравнение zero-shot. Без ретроспективного перевода закрытых групп в другую категорию.

<a id="6-reproducibility-and-final-freeze"></a>

## 6. Воспроизводимость и итоговая фиксация

До открытия итоговых результатов отрепетировать метрики/отказы/генерацию отчёта на разработке и зафиксировать:

| Блок реестра | Обязательное содержимое |
|---|---|
| Физическая задача/данные | Координатная система/сектор/угол места/правило дальности; наличие источника; фактические координаты/порядок/апертура и неопределённость; калибровка такта/усиления/фазы и истина источника; неизменяемые raw/хеши/повторное открытие/копии и ID групп/доступа/разбиения |
| Симуляция | Компоненты/истинная D, среда и граничные допущения, ревизия/сборка/точность решателя/хеши входов, поприёмные проверки задержки/фазы/полного отклика/сходимости/эталона, правила отклонения/замены и определения SNR |
| Вход/E | Частоты/единицы/полоса/окно/FFT/hop/масштабирование/дополнение/поддержка/нормировка; общий гибридный комплексный блок/упаковка, выбранный размер, ядра/шаги/привязка, позиции/состояние нормировки, область времени/обоснование локального изменения внимания, смешивание частот и оси/типы выходов |
| Fusion/голова | Попозиционное TF-соответствие внимания датчиков, `r_0,L_0,f_0`, координатная/частотная MLP и привязка, блок/головы/FFN/нормировка, маски датчиков/TF и порядок агрегации, пустой вход/ветвь без координат; C→C→2, цель в радианах, суммарная MSE, atan2/tau/отказы |
| JEPA | Вариант/доступ/происхождение цели, проба и допуск замороженного E до этапа 2, происхождение checkpoints, закон/покрытие `N_good,K,H`, предиктор всех позиций/цель EMA до агрегации/потеря только скрытых, масштаб/нормировка/коллапс и утечки; параллельные головы одного checkpoint и контроли с нуля/только этапа 1 |
| Сравнение и вывод | Настройки классики, seeds/пары, пригодные строки, бюджеты/выбор/остановки, предсказания единиц, исключения/отказы, агрегация/интервалы/множественность и обоснованные пороги |
| Ресурсы/артефакты | ID кода/данных/конфигурации/checkpoint; аппаратура/ПО/вычислительная реализация/точность; параметры, формы/батч/параллелизм, пиковые память и время; сгенерированные таблицы/рисунки/карта утверждений; дополняемый реестр итогового доступа |

Измерять полные прямой/обратный проходы E/Fusion/головы и фактическое применение с предобработкой; записывать реальные `N_ch,F_e,T_e,C`, ширины внимания/головы и вычислительную реализацию. Отдельно показывать генерацию симуляции/ввод-вывод, SSL E и Fusion, учителей/предикторы/пробы/выбор, каждую последующую ветвь и обучение с нуля. Длительность наблюдения и полная задержка — не пропускная способность кэша; двунаправленная обработка ограниченного окна не доказывает причинную обработку в реальном времени. Теоретическое число пар — не измеренные FLOPs/память. Невыполненные резервные размеры не являются отсутствующими обязательными ветвями.

Изменения сектора/метрики/модели/классики/доступа/пригодных единиц после просмотра результатов лишают исходную подтверждающую интерпретацию силы и должны раскрываться. Открыто исправлять ошибки достоверности; не сохранять неверный результат ради даты фиксации. Неудачная проверка такта/истины/фазы/эталона/маски/перестановки/повторного запуска блокирует затронутые выводы. Если нет безопасно полученных пригодных зимних данных, натурные M1/M4 не завершены и требуют явно согласованного с руководителем запасного плана — не симуляционной подмены.

## 7. Реестр утверждений и доказательств

Допустимые статусы: **поддержано, частично поддержано, не поддержано, ещё не оценено**. Матрица задаёт будущую проверку; готовый документ не означает её прохождения.

| Возможное утверждение | Необходимые доказательства | Ограничение / нулевой исход |
|---|---|---|
| Воспроизводимый подлёдный набор/протокол | Raw/истина/неопределённость/калибровка/QA/реестры, независимые группы и закрытый доступ | Отсутствие зимних данных показывается, не заменяется симуляцией |
| Вклад координат | Сопоставимая пара и диагностика наблюдаемости/контрольные проверки без координат | Только информационный компонент, не широкая новизна/перенос геометрии; положительный эффект не обязателен |
| Практический оцениватель на измеренной решётке | Результаты обучения с нуля/JEPA, MVDR/MUSIC и диагностика на закрытых группах | Ограниченный набор сравнений; показывать проигрыши/хвосты/отказы, не широкое SOTA-превосходство |
| S zero-shot из симуляции в натуру | Без подгонки по реальным сценам; зафиксированные методы на нетронутых полевых группах | Только сдвиг домена измеренного массива; неудача — ограниченный отрицательный результат |
| Основное трёхэтапное JEPA | Сначала допуск E; Fusion с потерей скрытых до агрегации; параллельные головы; сопоставимые контроли с нуля/только этапа 1, где выполнимо, учёт доступа и стоимости | Нет гарантии фазового/DOA-выигрыша; формальный минимум всех стадий ожидает решения руководителя; показывать заблокированные/невыполненные этапы |
| Дополнительный эффект представления/адаптации/геометрии | Заранее заданное сравнение, подходящая сопоставимость данных/физики, независимые группы, ресурсы/неопределённость | Только проверенный режим/домен; адаптация — не zero-shot, симуляция — не новая физическая топология |
| Достаточность диссертации | Оценка фактических доказательств/вкладов руководителем, по специальности и публикационным требованиям | Ни выигрыш, ни строгий нулевой результат, ни набор данных сами по себе не гарантируют новизну, степень или публикацию |

**Следующий допуск:** измерить аппаратуру/входную обработку и ресурсные ограничения, задать цели/пороги считывателя этапа 1 и разрешённые данные, затем реализовать ограниченный пилот E. Ни одно утверждение здесь не разрешает пропустить независимые зимние измерения.
